# 教師データ比較・失敗分析（2026-10-08）

## 今回の更新

- Xは品質Tierと区別する。「内容が弱い」と明示されたXだけを低評価Dの教師とし、対象外・AI生成・理由不明などのXは品質モデルから除外して理由別に集計する。既存の手動Tier、除外設定は書き換えない。
- 特徴抽出の成功・失敗・未取得をTier別、教師の出所別、記録済み原因別に集計する。古いVIDEO_UNAVAILABLEにはHTTPステータスがないため、404等を推測しない。URLや生のエラーメッセージは報告に含めない。
- 手動Tierだけのモデルと、参考アカウント評価を統合したモデルを比較する。手動評価を優先し、同じ投稿を重複して数えない。
- 投稿者と同一特徴のグループを保ったまま、学習・調整・最終検証に分割する。比較する両モデルの調整・最終検証には、同じ手動評価動画だけを使う。
- 調整データで方式を選び、最終検証の結果を見て方式を変更しない。合格した検証済みの学習ヘッドをそのまま候補として保存し、最終検証動画を含めて再学習しない。
- 以前の結果も観測済みの教師群を用いた開発比較であり、完全に新しい独立評価ではない。今後追加した手動評価動画で追試する。
- 自動採用やTier変更は行わず、既存の合格条件を維持する。失敗分析は原因の記録状況に左右され、今回の変更で精度が改善するとはまだ断定できない。

## PCでの適用手順

1. 同じチャットをPCで開き、`xclip-tier-teacher-improvements-20261008.ps1` をDownloadsに保存する。
2. 開発サーバーをCtrl+Cで停止する。
3. 次を実行する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\xclip-tier-teacher-improvements-20261008.ps1" -Project "C:\Projects\xcliprank"
```

4. プロジェクトフォルダーから起動する。

```powershell
cd C:\Projects\xcliprank
npm run dev -- --hostname 127.0.0.1 -p 3004
```

5. http://localhost:3004/tier-personal-model を開き、「保存済み特徴で2方式を比較（動画取得なし）」を押す。
6. 画面を開いたまま検証完了まで待つ。今回はキャッシュだけを使用するので、FFmpegパスの設定や動画の再ダウンロードは不要。特徴がない動画は補充せず、件数を報告する。
7. 「比較結果をJSONで保存」を押して、このチャットに添付する。
8. 実データの結果を確認するまで、モデル採用や過去動画への適用は保留する。

SQL変更、X API呼び出し、本番デプロイは不要。インストーラー自体はDBへ接続しない。比較ボタンは学習設定・診断結果・候補モデルを共通学習テーブルに保存するが、postsのTierは更新しない。

## 見る項目

- `diagnostics.byTier / bySource`: 特定のTierや出所で失敗率が高くないか。
- `diagnostics.causes / causesByTier`: 失敗原因の件数とTierの偏り。
- `diagnostics.xReasons / excludedX / weakXAsD`: Xの理由別件数と取り扱い。
- `validation.candidates`: 両方式の調整用・最終検証結果。
- `validation.selectedMode`: 調整用で選んだ方式。
- `validation.passed / failures`: 合格可否と不合格条件。
- `partition / missingFeatures`: データ数不足、未取得による比較の限界。

Xの取り扱いと検証対象を変更しているため、旧画面の19.8%と新画面の数字をそのまま改善幅として比較しない。新しい同一条件での「従来方式 vs 候補モデル」を評価する。
