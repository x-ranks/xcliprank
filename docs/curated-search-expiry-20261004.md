# 検索期限切れの整理（2026-10-04）

X Recent Searchは直近7日を対象とする。
公式仕様: https://docs.x.com/x-api/posts/search/quickstart/recent-search

- 一部だけ期限切れ: 開始時刻を検索可能期間内（5分の余裕を確保）へ寄せる。未取得ページのuntilId、元の検索終了時刻、取得済み最新IDは保持する。
- 残り全部が期限切れ: スキップ範囲を記録し、元の検索終了時刻から15分だけ重ねた次の窓へ切り替える。その開始も検索可能期間内へ制限する。時間とID境界をAPIへ混在させず、再開はIDだけを送る。
- 検索不能な未取得分は自動で有料の過去検索へ回さない。保存済み動画は削除・再取得しない。整理時点で最終成功時刻・成功投稿IDを進めない。
- 記録はauthors.curated_search_expiryへ保存。直近20回の範囲と累計回数を保持。期間境界は5分の安全余裕を含むため、記録は実際のAPI検索不能境界より保守的。
- 元のpendingと監査値が同じときだけ更新する。競合やDB書込失敗はX API呼び出し前に停止。正常なpendingは変更せず、同じ整理を繰り返しても監査を増やさない。
- cleanup-curated-expiry.cjsはDBのみ操作し、収集モジュール/Xクライアントを読み込まない。元の成功カーソル・postsは変更しない。
- 通常Cronでも収集前に同じ整理を行う。通常の1投稿者50件上限・公平な順番・429で停止・予算制限・安全フィルタ・DB重複排除を維持。通常CronのX API読み取りは従来どおり費用が発生し得る。

導入順: SQLで監査列を追加 → 新コードを隔離環境で検証 → 既存AppRootを保って切替 → 公開確認 → DBだけで期限状態を整理。テスト目的の24投稿者収集は実行しない。
