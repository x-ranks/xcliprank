# A/Sの取りこぼしを減らす比較候補

今回の50件プレビューでは、予測を見ずに評価した品質46件のうち、手動S/Aは20件、モデルもS/Aとしたのは5件。S/A/その他の一致率は63.0%だが、高評価動画の拾い上げ率は25%。低評価26件のS/A過大評価は0件だった。完全一致だけを追わず、良い動画がランキング対象から落ちる点を改善する。

## 変更内容

- 既存4方式に「A/S取りこぼし回復」を追加。同じ手動教師から学習した順位モデルを使う。
- SとAのスコアが分散し、どちらか単独の確信が不足してCへ戻る場合に、S/A合計のスコアと低評価との差を確認し、十分な証拠があればAを返す。
- S条件は維持。S条件未達を無条件にSへ昇格させない。
- 合計スコアの下限0.55/0.65/0.75/0.85と、低評価との差0.05/0.15/0.25を調整用データだけで比較する。これらはモデル内のスコアであり、実際の正解確率ではない。
- 既存の順位モデルより低評価→S/A、低評価→Sの率を増やさず、A/S拾い上げ率とTier一致率を下げない条件のみ候補にする。改善条件がない場合は既存方式を維持。
- A/S拾い上げ率とA/S適合率を比較表に追加。
- 最終検証のラベル・プレビューメモを使って閾値を選ばない。これまで観測した教師群による開発比較なので、新しい動画でも確認する。

## PCへの導入

開発サーバーを起動しているPowerShellでCtrl+Cを押す。別のPowerShellでインストーラーを実行する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\xclip-tier-high-recall-20261008.ps1" -Project "C:\Projects\xcliprank"
```

起動するPowerShellでは次の順番で実行する。

```powershell
cd C:\Projects\xcliprank
$env:XCLIP_FFMPEG_PATH = "C:\Projects\xcliprank\.local-admin\ffmpeg\ffmpeg.exe"
$env:XCLIP_FFPROBE_PATH = "C:\Projects\xcliprank\.local-admin\ffmpeg\ffprobe.exe"
npm run dev -- --hostname 127.0.0.1 -p 3004
```

1. http://localhost:3004/tier-personal-model を開く。
2. 「保存済み特徴で候補モデルを比較（動画取得なし）」を押して検証完了を待つ。教師動画の再取得はしない。
3. 比較表の「動画プレビューで試す手動候補」と、A/S拾い上げ率・適合率・過大評価率を確認し、「比較結果をJSONで保存」。回復候補が選ばれなくても正常。調整データ上で安全な改善が見つからなかったことを示す。
4. http://localhost:3004/tier-video-preview で新しいランダム50件のお試し比較を作成。以前確認した動画は新しい抽選から除外される。生成時には動画のダウンロードと4フレーム抽出が必要になる場合があるが、X API収集はしない。
5. 予測を表示する前に動画を再生して評価し、その後に比較する。完全一致よりも、手動S/AがB/Cのままになっていないか、低評価動画をS/Aに上げすぎていないかを確認する。
6. プレビューのJSONと比較結果のJSONを共有して実データの精度を確認する。

この更新は候補比較とプレビュー用。新方式は自動採用しない。保存済み動画のTier、手動評価、本番ランキングは更新しない。SQL変更、X API収集、本番デプロイは不要。特徴キャッシュと手動教師データは保持する。

## 検証の範囲

合成特徴によるA/S回復、S抑制、低評価維持、調整用データの条件不足、最終ラベルが候補選択に影響しないこと、および保存済み特徴を使う処理をテストする。アップロードJSONには動画特徴や学習済み重みが含まれないため、新モデルが実動画で改善するかはPC上での比較と新しいプレビューで確認する。
