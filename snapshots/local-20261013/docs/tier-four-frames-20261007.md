# 共通Tier学習：4フレーム版

既存の動画Tierレビューと参考教師評価を正解として、動画の10%・25%・50%・80%から4枚を切り出す。各画像の256次元特徴を時間順に連結し、1024次元の入力から手動Tierを学習する。100秒なら10秒・25秒・50秒・80秒。学生動画も同じ位置・画像処理・モデルで判定する。

## 導入
1. 先日の `xclip-personal-tier-20261006.ps1` をまだ適用していない場合も、今回のインストーラーにはその共通学習機能を含めている。
2. 開発サーバーをCtrl+Cで止める。今回のPowerShellインストーラーを実行する。変更前のファイルをバックアップし、別ブランチを作成する。既存ファイルの内容が想定と異なると書き換え前に停止する。
3. 前日のSQLを未実行なら `sql/tier-personal-model.sql` を本番と同じSupabaseプロジェクトのSQL Editorへ貼り付け、一度実行する。既に実行済みなら追加SQLは不要。
4. FFmpeg/FFprobeがなければPowerShellで `winget install --id Gyan.FFmpeg --exact` を実行する。PowerShellを開き直してPATHを反映する。`ffmpeg -version` と `ffprobe -version` で確認する。独自配置は `XCLIP_FFMPEG_PATH` と必要なら `XCLIP_FFPROBE_PATH` で指定可能。
5. プロジェクトで `npm run dev -- --hostname 127.0.0.1 -p 3004` を起動する。
6. `http://localhost:3004/learning-tools#operations` の「共通Tier学習・見た目の評価」を開き「教師データを統合して自動学習を有効化」を押す。

## 学習と再評価の流れ
1. 教師動画の4フレームを1動画ずつ抽出し、元の手動Tierで学習・検証する。評価を付け直す必要はない。
2. 検証条件を満たした候補を共通モデルに採用する。採用条件は前日の方式と同じ。本人の実データで精度が改善するかは未確認。
3. 「保存済み未評価動画の4フレーム準備・再開」を押すと、教師の処理後に保存済み・公開可能・未評価の動画を1件ずつ準備する。準備だけではTierやランキングを書き換えない。「一時停止」で止め、再開ボタンで続きから再開できる。
4. 「未評価動画の再評価・50件確認」で変更予定を計算し、適用する。教師以外の動画は教師データではなく、モデルによる予測対象。自動予測を正解の教師として自己学習しない。
5. 再評価は、未準備の動画も1件ずつ抽出できる。取得失敗は従来評価へ戻る。本人の手動Tier・安全上の除外・同時更新の保護を維持する。

## 動作の範囲
- サムネイル版と特徴仕様を分離し、古い256次元モデルを新しい1024次元特徴に適用しない。
- 元の4フレーム視覚好みモデル（10/35/65/90%）とも仕様が異なるため混ぜない。
- 各時点の特徴を平均だけに潰さず保持するので、時間位置ごとに違う重みを学べる。ただし4枚の静止画であり、連続した動作や全場面を理解するモデルではない。
- 起動中のローカル管理画面を開いている間に処理する。閉じると次回に再開する。複数画面でもDBリースで処理を直列化する。
- X APIを呼ばず、24投稿者の収集を再実行しない。動画URLからの取得通信、FFmpegと画像モデルのCPU、Supabaseの読取・保存は発生する。
- 動画は一時ファイルへ取得し、処理後に削除する。保存するのは特徴。1動画96MiB・再生1時間まで、ダウンロード60秒・各画像のデコード30秒を上限とする。
- 4枚すべてが取れなければ不完全な特徴は使わない。期限切れ・取得不能・上限超過は失敗数として残し7日間再取得を控える。FFmpeg不在は全動画を失敗登録せず、設定エラーとして停止する。
- 今回はローカル用コード。ColorfulBoxへの配置・そこでのFFmpeg利用可否は未確認。本番の収集中に4フレーム評価を使うには、コード・ツール配置と画像処理の明示的な有効化が必要。既定の収集は従来方式で継続する。

## 検証
4色の場面が順に変わる実際のテスト動画を使い、0.4秒・1秒・2秒・3.2秒で赤・緑・青・黄を取得できること、特徴が時間順に1024次元となることを確認する。実際の画像モデルを使う。これを本人動画での精度向上の証拠とはしない。
