# 共通Tier学習 初版

## 初回設定
1. ローカル開発サーバーをCtrl+Cで止め、付属のPowerShellインストーラーを実行する。
2. `sql/tier-personal-model.sql` を本番と同じSupabaseプロジェクトのSQL Editorで一度実行する。
   既存投稿のTierを変更せず、学習用3テーブルと手動評価変更通知を追加する。anon/authenticatedにはアクセス権を付けない。
3. `npm run dev -- --hostname 127.0.0.1 -p 3004` で起動し、`http://localhost:3004/learning-tools#operations` の「共通Tier学習・見た目の評価」を開く。
4. 「教師データを統合して自動学習を有効化」を押す。参考アカウントの既存評価をDBへ教師用データとして取り込み、DB手動評価を優先する。投稿そのものや手動Tierは書き換えない。
5. 管理画面を開いている間にサムネイルを2件ずつ抽出して検証する。閉じてもDBの特徴キャッシュが残り、次回に再開できる。失敗は7日間再取得を控える。
6. 最初の候補が検証条件を満たした場合のみ「検証を通過した候補を共通モデルに採用」を押せる。以後、手動レビューによる変更を検知し、合格した更新だけ自動採用する。不合格なら既存モデルを保持する。

## 普段の操作
- 動画Tierレビューを続ける。従来の視覚好みモデル学習を毎回手動で行う必要はない。
- 自動学習が進むのは、この新画面・動画Tierレビュー・learning-toolsを開いている間。24時間常駐やブラウザを閉じた後の実行ではない。
- 参考アカウント教師レビューを使い続ける必要はない。そこで追加評価したデータを取り込む場合だけ、有効化ボタンをもう一度押す。
- 過去の未評価動画へ反映する場合は既存の再評価画面でプレビュー後に適用する。手動評価済み動画は保護される。

## 学習方法と範囲
- 既存nsfwjsパッケージのMobileNetV2のflatten_1内部特徴を凍結して利用し、固定の符号付き256次元射影を行う。
- 個人のTierを正則化ソフトマックス分類器で教師あり学習する。平均特徴との距離だけで判定していた比較候補とは別方式。
- OTHERはB/C/Dの集合ラベルとして損失を計算し、勝手にBという教師ラベルを付けない。低評価X予測は自動判定上Dに変換し、安全ブロックと混同しない。
- 初版はサムネイル1枚が入力。動画内の動き、全場面、細部を理解するモデルではない。以前の4フレームキャッシュと特徴仕様が異なるので、そのキャッシュは混ぜない。
- 画像特徴が教師の好みを表現できるかは実データで確認が必要。精度が改善しなければ4フレーム動画特徴や別の特徴抽出器への拡張が次の作業。

## 検証と反映
- 投稿者と同一特徴を同じグループにして約20%を検証用に分離する。
- 学習100件・検証50件以上、検証S/A/OTHER各10件以上が必要。
- 従来のルール混合後の最終Tierを基準に、分類一致率と細かいTier一致率が下がらず、平均F1が2ポイント以上向上し、S/A再現率と低評価動画の誤昇格率が悪化しないことを採用条件とする。
- 従来方式のメタデータ教師はこれまで通りDB手動評価を使用する。参考評価の統合は新しい視覚学習側に行い、未検証の参考評価を従来方式へ混ぜない。
- 視覚予測の最大確率が0.6未満なら従来方式へ戻す。この同じ条件で検証する。
- 検証を何度も見て方式を調整すると、その検証セットは独立した最終確認用ではなくなる。継続改良後は未使用の新しい手動評価で最終確認する。
- 画像が取れた動画だけの検証なので取得可否による偏りは残る。全ての投稿での改善を保証しない。

## 本番収集への反映
- このインストーラーはWindowsのローカルコードを変更する。本番サーバーへ自動配置しない。
- 共通モデルと教師の参考評価は同じSupabaseに保存するため、本番へこの接続コードを配置した後は同じモデルを読み込める。
- 本番の選別投稿者収集では画像抽出が既定で無効。`XCLIP_VISUAL_COLLECTION=1` を設定した場合だけ、1プロセス1分あたり4件まで抽出する。API読取数や24投稿者の収集量は増やさない。
- 特徴未取得・画像取得失敗・予測信頼度不足・モデル未採用なら従来のメタデータ評価で保存する。全動画の即時視覚評価を保証しない。
- 過去動画の再評価は同じ共通モデルを固定して使い、画像抽出が必要なため5件ずつ計算する。比較更新による手動評価・安全フラグ保護は維持する。
- X API呼び出しなし。ただし画像の通信、CPU、Supabaseの保存・読取は発生する。

## ロールバック
- 新画面の「視覚モデルの適用を解除」で視覚モデルと自動採用を停止できる。
- コードはインストーラーが表示したバックアップから戻せる。学習テーブルを消す必要はない。
- 既に再評価で適用した自動Tierは、適用解除だけでは元に戻らない。再評価の変更履歴を保存してあるので個別に扱う。
